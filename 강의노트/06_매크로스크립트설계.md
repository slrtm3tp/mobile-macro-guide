## 📚 **학습 목표 (Learning Objectives)**

이번 장을 마치면 여러분은 매크로를 "동작 목록(STEPS)"으로 표현하고, 목록을 읽어 차례로 실행하는 실행기를 만들 수 있습니다. 또한 실패한 단계를 다시 시도하고, 실행 기록(로그)과 오류 화면을 남기며, 여러 번 반복 실행하는 튼튼한 매크로 구조를 설계할 수 있게 됩니다.

## 1️⃣ **코드와 데이터를 나누기**

매크로를 처음 만들면 보통 이렇게 씁니다.

```python
tap(440, 440)
time.sleep(2)
tap_text("이벤트")
time.sleep(1)
swipe(720, 2400, 720, 1200, 400)
```

동작은 하지만, 순서를 바꾸거나 단계를 추가하려면 코드를 고쳐야 합니다. 대신 **"무엇을 할지"를 목록(데이터)**으로 적고, **"어떻게 할지"는 실행기(코드)**가 맡도록 나눕니다.

```
데이터 (STEPS)                          코드 (실행기)

 [("tap", 440, 440),        ──────►   for step in STEPS:
  ("wait", 2),                            종류를 보고
  ("tap_text", "이벤트"),                  알맞은 함수 호출
  ("swipe", 720, 2400, ...)]

  ✔ 매크로 수정 = 목록만 수정
  ✔ 실행기는 한 번 만들면 계속 재사용
```

## 2️⃣ **STEPS: 동작을 튜플로 표현하기**

```python
# 기본 구조: (동작 이름, 인자1, 인자2, ...)
STEPS = [
    ("launch", "ctrip.english"),
    ("wait", 3),
    ("tap_text", "이벤트"),
    ("swipe", 720, 2400, 720, 1200, 400),
    ("key", "KEYCODE_BACK"),
]
```

튜플의 첫 번째 값은 동작 이름, 나머지는 그 동작에 필요한 값입니다.

| 동작 | 쓰는 법 | 하는 일 |
| --- | --- | --- |
| `tap` | `("tap", 540, 1200)` | 좌표 탭 |
| `swipe` | `("swipe", 540, 1600, 540, 600, 300)` | 스와이프 |
| `key` | `("key", "KEYCODE_BACK")` | 키 입력 |
| `text` | `("text", "hello")` | 영문 입력 |
| `wait` | `("wait", 1.5)` | 초 단위 대기 |
| `launch` | `("launch", "ctrip.english")` | 앱 실행 |
| `stop` | `("stop", "ctrip.english")` | 앱 종료 |
| `open` | `("open", "URL", "패키지명")` | 주소로 바로 열기 (7장) |
| `tap_text` | `("tap_text", "이벤트")` | 글자 찾아 탭 |
| `wait_for` | `("wait_for", "완료", 15)` | 글자가 나타날 때까지 대기 |
| `shot` | `("shot", "결과")` | 시간이 붙은 이름으로 캡처 |

## 3️⃣ **실행기 만들기: run_step**

```python
def run_step(step):
    kind, *a = step          # 첫 값은 kind, 나머지는 리스트 a
    if kind == "tap":
        tap(*a)
    elif kind == "swipe":
        swipe(*a)
    elif kind == "wait":
        time.sleep(a[0])
    elif kind == "tap_text":
        tap_text(*a)
    # ... 나머지 동작들
    else:
        raise ValueError(f"알 수 없는 동작: {kind}")

for step in STEPS:
    run_step(step)
```

`kind, *a = step`은 **언패킹**입니다. `("swipe", 720, 2400, 720, 1200, 400)`이라면 `kind = "swipe"`, `a = [720, 2400, 720, 1200, 400]`이 됩니다.

## 4️⃣ **고정 대기 vs 조건 대기**

```
고정 대기: ("wait", 5)                  조건 대기: ("wait_for", "할인쿠폰", 15)

 항상 5초를 기다림                        나타나면 즉시 다음으로
  - 빨리 뜨면: 시간 낭비                    - 0.8초 만에 뜨면: 0.8초만 기다림
  - 늦게 뜨면(6초): 실패                    - 늦게 뜨면(6초): 6초 기다림
                                          - 15초 지나도 없으면: 실패라고 알려 줌
```

네트워크 속도나 폰 상태에 따라 로딩 시간은 매번 다릅니다. **화면이 바뀌는 곳에는 `wait_for`**를 쓰고, `wait`는 애니메이션이 끝나기를 기다리는 짧은 시간(0.5~1초)에만 씁니다.

## 5️⃣ **실패 대비: 재시도와 오류 기록**

### **재시도**

일시적인 문제(로딩 지연, 잠깐 뜬 팝업)는 다시 시도하면 해결되는 경우가 많습니다.

```python
RETRIES = 2

def run_with_retry(step):
    for attempt in range(1, RETRIES + 2):     # 1, 2, 3 → 처음 + 재시도 2번
        try:
            run_step(step)
            return True
        except AdbError as e:
            log(f"   ⚠️ 실패 ({attempt}회차): {e}")
            time.sleep(1)
    return False
```

### **로그 (실행 기록)**

매크로가 밤사이 혼자 돌다가 실패했다면, 무슨 일이 있었는지 알아야 합니다. 화면 출력과 동시에 파일에도 남깁니다.

```python
import datetime

def log(msg):
    line = f"[{datetime.datetime.now():%H:%M:%S}] {msg}"
    print(line)
    with open("macro.log", "a", encoding="utf-8") as f:   # "a" = 이어 쓰기
        f.write(line + "\n")
```

### **실패 순간의 화면 남기기**

```python
if not run_with_retry(step):
    path = screenshot(f"error_{datetime.datetime.now():%H%M%S}.png")
    log(f"❌ {i}단계에서 중단. 화면을 {path}에 저장했습니다")
```

오류 캡처를 보면 "팝업이 덮고 있었다", "로그인이 풀렸다" 같은 원인을 바로 알 수 있습니다.

## 📝 **핵심 개념 정리**

매크로는 "무엇을 할지"인 STEPS 목록과 "어떻게 할지"인 실행기로 나누어 설계합니다. STEPS는 `(동작 이름, 인자...)` 튜플의 리스트이고, 실행기 `run_step`은 `kind, *a = step`으로 꺼내 알맞은 함수를 호출합니다.

화면이 바뀌는 곳에는 고정 대기 대신 `wait_for`로 조건 대기를 합니다. 실패에 대비해 재시도(`run_with_retry`), 로그 파일(`macro.log`), 오류 순간 캡처를 남기면 혼자 돌다 실패한 매크로도 원인을 찾을 수 있습니다.

실행기를 한 번 만들어 두면 STEPS만 바꿔서 얼마든지 새로운 매크로를 만들 수 있습니다.

## 🔑 **퀴즈 정답 및 해설**

**1번 정답: 3**
`*a`는 남은 값을 모두 **리스트**로 받습니다. `kind`는 `"swipe"`입니다.

**2번 정답: 3**
`"a"`(append)는 파일 끝에 이어 씁니다. `"w"`는 파일을 지우고 새로 씁니다.

**3번 정답: 3**
`wait_for`는 나타나는 즉시 다음으로 넘어가고, 15초까지 기다려 줍니다. 1번은 늦게 뜰 때 실패하고, 2번은 빨리 뜰 때 7초를 낭비합니다.

**4번 정답: 3**
`range(1, RETRIES + 2)`는 1, 2, 3이므로 처음 1번 + 재시도 2번 = 최대 3번입니다.

**5번 정답: 3**
구조를 나눈다고 실행 속도가 빨라지지는 않습니다. 이 설계의 장점은 수정과 재사용이 쉬워진다는 것입니다.
