# 4장 누를 위치 찾기: 좌표와 화면 요소

---

## 📚 **학습 목표 (Learning Objectives)**

이번 장을 마치면 여러분은 화면에서 누르고 싶은 곳의 좌표를 세 가지 방법으로 찾을 수 있습니다. 또한 `uiautomator dump`로 화면 구조(XML)를 읽고, 버튼의 글자·설명·ID·위치(bounds)를 해석하여 "글자로 버튼 찾기"의 원리를 이해하게 됩니다.

---

## 1️⃣ **좌표 방식 vs 화면 요소 방식**

매크로가 버튼을 누르는 방법은 크게 두 가지입니다.

```
좌표 방식                                화면 요소 방식

 "(400, 1200)을 눌러라"                   "'이벤트'라고 쓰인 버튼을 찾아서 눌러라"
       │                                        │
       ▼                                        ▼
  항상 그 위치를 누름                       화면을 읽어 버튼 위치를 계산 → 누름

  ✔ 빠르고 간단                             ✔ 버튼 위치가 바뀌어도 동작
  ✘ 화면 배치가 바뀌면 엉뚱한 곳을 누름        ✔ 버튼이 없으면 "없다"고 알 수 있음
  ✘ 다른 해상도 폰에서는 다시 찾아야 함        ✘ 화면을 읽는 데 1~2초 걸림
                                           ✘ 이미지로만 된 버튼은 못 찾음
```

결론부터 말하면, **가능하면 화면 요소 방식을 쓰고, 안 될 때만 좌표**를 씁니다.

---

## 2️⃣ **좌표 찾기 방법 1: 포인터 위치**

가장 쉽고 정확한 방법입니다.

```
설정 → 개발자 옵션 → 포인터 위치 (켜기)
```

켜면 화면 맨 위에 터치한 위치의 좌표가 실시간으로 표시됩니다.

```
┌──────────────────────────────────────────┐
│ P: 1/1   X: 403.5   Y: 1211.2   Xv: 0.0 ...│  ← 이 줄의 X, Y를 읽음
├──────────────────────────────────────────┤
│                                          │
│         ┌────────────┐                   │
│         │  이벤트 ●   │ ← 여기를 터치       │
│         └────────────┘                   │
```

ADB 명령으로도 켜고 끌 수 있습니다.

```bash
adb shell settings put system pointer_location 1   # 켜기
adb shell settings put system pointer_location 0   # 끄기
```

## 3️⃣ **좌표 찾기 방법 2: 스크린샷**

1. `adb exec-out screencap -p > screen.png`로 캡처합니다.
2. 이미지를 **원본 크기**로 엽니다. (Mac 미리보기: `도구 → 크기 조절`에서 픽셀 크기 확인)
3. 누를 위치의 픽셀 좌표를 읽습니다.

> ⚠️ 이미지 뷰어가 이미지를 축소해서 보여 주면 좌표가 틀립니다. 캡처 이미지 크기가 폰 해상도(예: 1440x3120)와 같은지 꼭 확인하세요.

### **축소된 이미지에서 좌표 변환하기**

이미지를 축소해서 봤다면 비율을 곱해 원래 좌표로 바꿉니다.

```
원래 좌표 = 축소 이미지 좌표 × (원본 너비 ÷ 축소 너비)

예) 1440px 이미지를 923px로 줄여서 봤을 때 (300, 700)을 찾았다면
    배율 = 1440 ÷ 923 ≈ 1.56
    원래 좌표 = (300 × 1.56, 700 × 1.56) = (468, 1092)
```

10장에서 자세히 배울 `scrcpy`로 폰 화면을 PC에 띄우고, 포인터 위치를 켠 상태에서 마우스로 클릭하면 PC에서 편하게 좌표를 확인할 수 있습니다.

```bash
brew install scrcpy
scrcpy
```

## 5️⃣ **화면 구조 읽기: uiautomator dump**

안드로이드는 화면에 있는 모든 버튼과 글자의 정보를 XML 문서로 꺼내 주는 기능이 있습니다.

```bash
# 1. 폰에서 화면 구조를 파일로 저장
adb shell uiautomator dump /sdcard/ui.xml
# UI hierchary dumped to: /sdcard/ui.xml

# 2. PC로 가져오기
adb exec-out cat /sdcard/ui.xml > ui.xml
```

### **XML 결과 살펴보기**

`ui.xml`을 열면 이런 줄이 수십~수백 개 들어 있습니다. (보기 좋게 줄을 나눴습니다.)

```xml
<node index="2"
      text="이벤트"
      resource-id="com.example.shop:id/tab_title"
      class="android.widget.TextView"
      package="com.example.shop"
      content-desc="이벤트"
      clickable="true"
      enabled="true"
      bounds="[320,400][560,480]" />
```

### **꼭 알아야 할 속성**

| 속성 | 의미 | 예 | 찾을 때 쓰임 |
| --- | --- | --- | --- |
| `text` | 화면에 보이는 글자 | `이벤트` | ★★★ 가장 많이 씀 |
| `content-desc` | 접근성 설명 (시각장애인용 음성 안내 문구) | `검색창` | 아이콘 버튼처럼 글자가 없을 때 |
| `resource-id` | 개발자가 붙인 요소 이름 | `com.example.shop:id/tab_title` | 글자가 바뀌어도 그대로 |
| `class` | 요소 종류 | `android.widget.Button` | 입력창(`EditText`) 찾기 |
| `clickable` | 누를 수 있는가 | `true` | 실제로 눌리는 요소인지 확인 |
| `bounds` | 위치와 크기 | `[320,400][560,480]` | 누를 좌표 계산 |

### **bounds에서 누를 좌표 계산하기**

```
bounds="[320,400][560,480]"
         └─┬─┘  └─┬─┘
         왼쪽 위   오른쪽 아래
         (x1,y1)   (x2,y2)

  (320,400) ┌──────────────┐
            │     이벤트    │
            │       ●      │ ← 가운데 = ((320+560)/2, (400+480)/2) = (440, 440)
            └──────────────┘ (560,480)
```

요소의 **가운데**를 누르는 것이 가장 안전합니다.

### **예제 1: 화면의 모든 글자 목록 보기**

XML 전체를 읽기는 어려우므로, 글자가 있는 요소만 골라 봅니다.

```bash
adb shell uiautomator dump /sdcard/ui.xml > /dev/null
adb exec-out cat /sdcard/ui.xml | grep -oE '(text|content-desc)="[^"]+"' | head -20
```

```
content-desc="검색"
text="설정"
text="연결"
text="Wi-Fi • 블루투스 • 비행기 탑승 모드"
text="소리 및 진동"
text="알림"
text="디스플레이"
text="밝기 • 다크 모드 • 화면 모드"
text="배터리"
text="잠금화면 및 AOD"
```

갤럭시 설정 앱 첫 화면의 예입니다. (메뉴 이름은 기기와 버전마다 조금씩 다릅니다.) 이 목록에 있는 글자는 모두 "글자로 찾아 누르기"가 가능합니다.

### **예제 2: 특정 글자의 bounds 찾기**

```bash
adb exec-out cat /sdcard/ui.xml | grep -oE 'text="디스플레이"[^>]*bounds="[^"]*"'
```

```
text="디스플레이" resource-id="android:id/title" ... bounds="[320,400][560,480]"
```

```bash
# 가운데를 계산해서 탭
adb shell input tap 440 440
```

5장에서는 이 과정을 Python으로 자동화하여 `tap_text("디스플레이")` 한 줄로 만듭니다.

## 6️⃣ **글자가 있는데 눌리지 않는 경우**

`text="이벤트"`인 요소의 `clickable`이 `false`라면, 실제로 눌리는 것은 그 요소를 감싸고 있는 **부모 요소**입니다.

```xml
<node clickable="true"  bounds="[300,380][580,500]">      ← 부모 (실제 버튼)
    <node text="이벤트" clickable="false" bounds="[320,400][560,480]" />  ← 글자
</node>
```

대부분은 글자 위치를 눌러도 부모 버튼이 반응하지만, 반응이 없다면 부모의 bounds 가운데를 누릅니다.

또한 화면 위에 다른 창이 덮여 있으면(예: 유튜브 PIP 미니 플레이어) 그 창이 터치를 가로챕니다. 캡처를 찍어서 덮인 창이 없는지 확인하세요.

## 7️⃣ **화면 요소 방식이 안 되는 경우**

| 상황 | 이유 | 대안 |
| --- | --- | --- |
| 배너·광고 이미지 | 글자가 그림 속에만 있음 | 좌표, 이미지 매칭(8장), 주소로 바로 열기(7장) |
| 게임 화면 | 게임 엔진이 직접 그림 | 좌표, 이미지 매칭 |
| 일부 웹페이지 화면 | 웹 내용이 요소로 안 잡힘 | 좌표, 이미지 매칭 |
| 계속 움직이는 화면 | dump가 실패하거나 오래 걸림 | 잠시 기다렸다가 다시 시도 |
| 보안 앱 | 화면 읽기 차단 | 매크로 대상에서 제외 |

### **예제 3: 이미지 배너 문제**

쇼핑·여행 앱의 홈 화면에는 여러 장의 이벤트 배너가 자동으로 넘어가는 경우가 많습니다. 이런 배너는 대개 그림으로만 되어 있어서, 배너에 "가을 세일"이라고 쓰여 있어도 XML에는 그 글자가 없습니다. 대신 배너 아래 쪽번호는 글자로 잡히는 경우가 있습니다.

```xml
<node text="6"   resource-id="com.example.shop:id/page_now"   bounds="[571,1703][595,1760]" />
<node text="/16" resource-id="com.example.shop:id/page_total" bounds="[595,1703][660,1760]" />
```

배너 내용은 읽을 수 없지만 "지금 몇 번째 배너인지"는 알 수 있다는 뜻입니다. 하지만 배너가 자동으로 넘어가면 화면을 읽는 1~2초 사이에 번호가 바뀌어 버립니다. 이런 화면은 7장의 "주소로 바로 열기"나 8장의 이미지 매칭으로 해결합니다.

## 📝 **핵심 개념 정리**

좌표 방식은 빠르지만 화면 배치나 해상도가 바뀌면 깨집니다. 화면 요소 방식은 글자나 ID로 버튼을 찾아 위치를 계산하므로 훨씬 튼튼합니다.

좌표는 개발자 옵션의 포인터 위치, 원본 크기 스크린샷, scrcpy로 찾을 수 있습니다. 축소된 이미지라면 배율을 곱해야 합니다.

`uiautomator dump`는 화면 구조를 XML로 꺼내 줍니다. `text`, `content-desc`, `resource-id`로 요소를 찾고, `bounds`의 가운데 `((x1+x2)/2, (y1+y2)/2)`를 누릅니다. 이미지 배너, 게임, 보안 앱처럼 요소가 잡히지 않는 화면은 좌표나 이미지 매칭, 주소로 바로 열기를 사용합니다.

## 🔑 **퀴즈 정답 및 해설**

**1번 정답: 2**
포인터 위치를 켜면 화면 위쪽에 X, Y 좌표가 표시됩니다. "터치 표시"는 터치한 곳에 점만 보여 줍니다.

**2번 정답: 2**
x = (100 + 300) / 2 = 200, y = (200 + 400) / 2 = 300입니다.

**3번 정답: 2**
`content-desc`는 접근성 설명으로, 글자 없는 아이콘 버튼에도 "검색" 같은 설명이 붙어 있는 경우가 많습니다.

**4번 정답: 3**
배율은 1080 ÷ 540 = 2입니다. (200 × 2, 500 × 2) = (400, 1000)입니다.

**5번 정답: 2**
화면 요소 방식은 글자로 버튼을 찾으므로 위치가 바뀌어도 동작합니다. 1, 3번은 요소가 잡히지 않아 좌표나 이미지 매칭이 필요하고, 4번은 화면 읽기 자체가 막혀 있습니다.
