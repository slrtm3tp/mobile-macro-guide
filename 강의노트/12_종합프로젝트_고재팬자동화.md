## 1️⃣ **프로젝트 소개와 요구사항**

트립닷컴의 "고재팬" 프로모션 페이지는 **매주 수요일**에 항공·호텔 쿠폰을 공개합니다. 매주 앱을 열고 배너를 찾아 들어가는 번거로움을 없애는 것이 목표입니다.

### **요구사항 정리**

| 번호 | 요구사항 | 사용 기술 (장) |
| --- | --- | --- |
| R1 | 폰이 연결되어 있지 않거나 잠겨 있으면 이유를 알려 주고 멈춘다 | 1장, 3장, 11장 |
| R2 | 화면을 덮는 앱(유튜브 PIP)을 정리하고 깨끗한 상태에서 시작한다 | 3장 |
| R3 | 배너를 찾지 않고 주소로 고재팬 페이지를 바로 연다 | 7장 |
| R4 | 페이지가 제대로 열렸는지 화면(액티비티)으로 확인한다 | 3장, 5장 |
| R5 | 원하면 특정 글자(예: "받기")를 찾아 누른다 | 5장 |
| R6 | 결과를 캡처하고, 실행 기록을 CSV와 로그로 남긴다 | 6장 |
| R7 | 정해진 시각에 실행하고, 매주 자동으로 돌게 등록한다 | 9장 |

> 💡 R5(버튼 누르기)는 선택 기능으로 둡니다. 쿠폰을 받는 버튼을 자동으로 누를지는 서비스 약관을 확인한 뒤 스스로 결정하세요 (11장).

## 3️⃣ **구현: 단계별 코드**

전체 코드는 [`예제코드/project_gojapan.py`](../예제코드/project_gojapan.py)에 있습니다. 중요한 부분을 나누어 살펴봅니다.

### **설정값 모아 두기**

```python
PACKAGE = "ctrip.english"
URL = "https://kr.trip.com/sale/w/37676/gojapan.html?locale=ko-KR&transparentBar=1&wkp=1"
H5_ACTIVITY = "TripH5Container"                 # 웹페이지를 띄우는 화면 이름
CLOSE_FIRST = ["com.google.android.youtube"]    # 화면을 덮을 수 있는 앱
OUT_DIR = "runs"
```

바뀔 수 있는 값은 코드 맨 위에 모읍니다. 다른 이벤트 페이지로 바꾸고 싶다면 `URL`만 고치면 됩니다.

### **R1: 깨우기와 잠금 확인**

```python
def wake_and_unlock_check():
    key("KEYCODE_WAKEUP")
    time.sleep(0.5)
    locked = "mDreamingLockscreen=true" in shell("dumpsys window | grep mDreamingLockscreen")
    if locked:
        raise AdbError("폰이 잠겨 있습니다. 잠금을 풀어 두거나 충전 중 화면 켜짐 유지를 켜세요")
```

잠금 화면을 매크로로 풀지 않습니다. 비밀번호를 스크립트에 적는 것은 위험하기 때문입니다 (11장).

### **R2~R4: 정리하고, 열고, 확인하기**

```python
def open_page():
    for pkg in CLOSE_FIRST:
        stop(pkg)                       # 유튜브 PIP 정리
    stop(PACKAGE)                       # 트립닷컴 완전 종료
    time.sleep(1)
    open_url(URL, PACKAGE)              # 주소로 바로 열기
    for _ in range(20):                 # 0.5초 x 20 = 최대 10초
        pkg, activity = current_app()
        if pkg == PACKAGE and activity and H5_ACTIVITY in activity:
            return True                 # 트립닷컴 웹페이지 화면 확인!
        time.sleep(0.5)
    return False
```

웹페이지 안의 글자는 XML에 잡히지 않을 수도 있으므로, **글자 대신 액티비티 이름으로 "제대로 열렸는지"를 확인**합니다. 이것이 7장에서 확인한 `TripH5Container`입니다.

### **R6: 실행 기록 남기기**

```python
def record(result, seconds, memo):
    path = os.path.join(OUT_DIR, "history.csv")
    new = not os.path.exists(path)
    with open(path, "a", newline="", encoding="utf-8-sig") as f:
        w = csv.writer(f)
        if new:
            w.writerow(["시각", "결과", "걸린 시간(초)", "메모"])
        w.writerow([datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S"), result, f"{seconds:.1f}", memo])
```

`encoding="utf-8-sig"`를 쓰면 엑셀에서 열어도 한글이 깨지지 않습니다.

### **실패해도 기록은 남기기: try / except**

```python
try:
    wake_and_unlock_check()
    if not open_page():
        raise AdbError("페이지 화면이 뜨지 않았습니다")
    ...
    result = "성공"
except AdbError as e:
    result, memo = "실패", str(e)

screenshot(...)                 # 성공이든 실패든 실행됨
record(result, seconds, memo)
```

## 5️⃣ **자동 실행 등록**

9장에서 배운 cron으로 매주 수요일 9시 59분에 실행되도록 등록합니다.

```bash
which python3      # 예: /opt/homebrew/bin/python3
crontab -e
```

```bash
59 9 * * 3 cd ~/Desktop/mobile-macro-guide/예제코드 && PATH=/opt/homebrew/bin:$PATH python3 project_gojapan.py >> cron.log 2>&1
```

| 부분 | 의미 |
| --- | --- |
| `59 9 * * 3` | 매주 수요일 9시 59분 |
| `cd .../예제코드` | `adb_helper.py`가 있는 폴더로 이동 |
| `PATH=/opt/homebrew/bin:$PATH` | cron에서도 `adb`, `python3`를 찾도록 |
| `>> cron.log 2>&1` | 출력과 오류를 로그로 |

### **등록 전 점검표**

- [ ] 터미널에서 `python3 project_gojapan.py`가 성공한다
- [ ] 폰이 충전 중이고 `충전 중 화면 켜짐 유지`가 켜져 있다
- [ ] 폰 화면 잠금이 없거나, 실행 시각에 잠금이 풀려 있다
- [ ] Mac이 그 시각에 잠자기 상태가 아니다 (또는 launchd 사용)
- [ ] 다음 날 `runs/history.csv`와 캡처로 결과를 확인한다

## 📝 **핵심 개념 정리**

좋은 매크로는 요구사항 정리 → 실행 흐름 설계 → 단계별 구현 → 실패 대비 → 기록 → 자동 실행 등록의 순서로 만듭니다.

이번 프로젝트에서는 주소로 바로 열어 배너 찾기를 없앴고(7장), 글자 대신 액티비티 이름으로 페이지가 열렸는지 확인했으며(3장), 방해 앱을 먼저 정리했습니다(11장). `try/except`로 실패해도 반드시 캡처와 CSV 기록을 남기도록 하여, 사람이 지켜보지 않아도 결과를 확인할 수 있게 했습니다.

바뀔 수 있는 값은 맨 위에 모으고, 버튼 누르기처럼 약관과 관련된 동작은 선택 기능으로 분리했습니다. 이 틀을 그대로 사용하면 다른 앱, 다른 이벤트의 매크로도 쉽게 만들 수 있습니다.

## 🔑 **퀴즈 정답 및 해설**

**1번 정답: 3**
배너는 이미지이고 자동으로 넘어가서 찾기 어려웠습니다. 주소로 바로 열면 한 단계로 끝납니다 (7장).

**2번 정답: 2**
`utf-8-sig`는 파일 앞에 표시(BOM)를 붙여 엑셀이 UTF-8임을 알아보게 합니다.

**3번 정답: 2**
웹페이지(H5) 화면은 내용이 XML 요소로 잡히지 않을 수 있습니다. 액티비티 이름(`TripH5Container`)은 항상 확인할 수 있습니다.

**4번 정답: 3**
`screenshot()`은 `try/except` 블록 밖에 있으므로 성공이든 실패든 항상 실행됩니다. 실패 원인을 알려면 실패할 때의 캡처가 특히 중요합니다.

**5번 정답: 4**
배경화면은 이 매크로(주소로 열기, 액티비티 확인)와 관계가 없습니다. 8장의 이미지 매칭을 쓴다면 영향을 줄 수 있습니다.
