## 📚 **학습 목표 (Learning Objectives)**

이번 장을 마치면 여러분은 글자도 주소도 없는 화면에서 버튼을 찾을 수 있습니다. OpenCV의 템플릿 매칭으로 스크린샷 속에서 버튼 그림의 위치를 찾고, 일치도(점수)를 해석하여 누를지 말지 판단하며, 자동으로 넘어가는 배너처럼 움직이는 화면을 다루는 방법을 익히게 됩니다.

## 1️⃣ **이미지 매칭이 필요한 순간**

```
버튼 찾기 방법 선택표

  주소가 있다?          ── Yes ──► 7장: 주소로 바로 열기
     │ No
     ▼
  XML에 글자/ID가 있다?  ── Yes ──► 5장: tap_text, find
     │ No
     ▼
  위치가 항상 같다?      ── Yes ──► 4장: 좌표
     │ No
     ▼
  이미지 매칭 (이번 장)
```

게임 버튼, 이미지 배너, 위치가 바뀌는 아이콘처럼 **글자로 찾을 수 없고 위치도 일정하지 않을 때** 이미지 매칭을 씁니다.

---

## 2️⃣ **템플릿 매칭의 원리**

찾고 싶은 버튼을 작게 잘라 둔 그림을 **템플릿**이라고 합니다. OpenCV는 템플릿을 화면 전체 위에서 한 칸씩 옮겨 가며 얼마나 비슷한지 점수를 매깁니다.

```
화면 (screen.png)                          템플릿 (button.png)
┌───────────────────────────┐               ┌─────────┐
│ ┌─────────┐ →  →  →       │               │ 쿠폰받기 │
│ │ 비교 중  │               │               └─────────┘
│ └─────────┘               │
│      ↓                    │   위치마다 점수 계산
│                           │   (0.12, 0.08, 0.31, ... 0.97 ← 최고점!)
│            ┌─────────┐    │
│            │ 쿠폰받기 │ ◄── 최고점 위치 = 버튼 위치
│            └─────────┘    │
└───────────────────────────┘
```

점수는 -1 ~ 1 사이이며 **1에 가까울수록 똑같습니다**. 보통 0.85 이상이면 "찾았다"고 판단합니다.

## 3️⃣ **OpenCV 설치와 기본 사용**


```python
# 기본 구조
import cv2

screen = cv2.imread("screen.png")      # 화면
tpl = cv2.imread("button.png")         # 템플릿
res = cv2.matchTemplate(screen, tpl, cv2.TM_CCOEFF_NORMED)
_, score, _, (x, y) = cv2.minMaxLoc(res)   # 최고 점수와 그 위치(왼쪽 위)
print(score, x, y)
```

```
0.9734 412 1085
```

| 함수 | 의미 |
| --- | --- |
| `cv2.imread(path)` | 이미지 파일을 배열로 읽기 |
| `cv2.matchTemplate(화면, 템플릿, 방법)` | 모든 위치의 점수 표 만들기 |
| `cv2.TM_CCOEFF_NORMED` | 밝기 차이에 강한 정규화 방법 (가장 많이 씀) |
| `cv2.minMaxLoc(res)` | 최저점, 최고점, 최저 위치, 최고 위치 |

`minMaxLoc`이 돌려주는 위치는 템플릿의 **왼쪽 위 모서리**입니다. 누를 때는 템플릿 크기의 절반을 더해 가운데를 계산합니다.

```python
h, w = tpl.shape[:2]          # 템플릿 높이, 너비
cx, cy = x + w // 2, y + h // 2
```

## 4️⃣ **템플릿 만들기**

좋은 템플릿이 성공률을 결정합니다.

### **예제 1: 화면에서 잘라 템플릿 저장하기**

```python
import cv2
import numpy as np
from adb_helper import adb

def grab_screen():
    png = adb("exec-out", "screencap", "-p")
    return cv2.imdecode(np.frombuffer(png, np.uint8), cv2.IMREAD_COLOR)

screen = grab_screen()
# 포인터 위치로 확인한 버튼 영역: x=400, y=1100, 너비 300, 높이 120
button = screen[1100:1100 + 120, 400:400 + 300]    # [y범위, x범위] 순서 주의!
cv2.imwrite("button.png", button)
```

> ⚠️ 이미지 배열은 `[세로(y), 가로(x)]` 순서로 자릅니다. 좌표의 (x, y) 순서와 반대이니 주의하세요.

`cv2.imdecode`는 파일로 저장하지 않고 메모리에서 바로 PNG를 이미지 배열로 바꿉니다. 캡처 → 저장 → 읽기를 한 번에 해서 빠릅니다.

### **좋은 템플릿의 조건**

| 좋은 템플릿 | 나쁜 템플릿 |
| --- | --- |
| 버튼의 글자·아이콘처럼 **특징 있는 부분** | 단색 배경만 있는 부분 |
| 버튼 테두리 **안쪽**만 자르기 | 주변 배경까지 크게 자르기 |
| 매크로를 돌릴 폰에서 직접 캡처 | 다른 폰·인터넷 이미지 |
| 바뀌지 않는 부분 (예: "쿠폰받기" 글자) | 숫자·시간처럼 바뀌는 부분 |

## 5️⃣ **찾아서 누르기: find_image, tap_image**

```python
def find_image(template_path, threshold=0.85):
    screen = grab_screen()
    tpl = cv2.imread(template_path)
    res = cv2.matchTemplate(screen, tpl, cv2.TM_CCOEFF_NORMED)
    _, score, _, (x, y) = cv2.minMaxLoc(res)
    if score < threshold:
        return None                          # 충분히 비슷한 곳이 없음
    h, w = tpl.shape[:2]
    return x + w // 2, y + h // 2, score

def tap_image(template_path, timeout=10):
    deadline = time.time() + timeout
    while time.time() < deadline:
        hit = find_image(template_path)
        if hit:
            tap(hit[0], hit[1])
            return hit
        time.sleep(0.5)
    raise RuntimeError(f"{template_path}를 찾지 못했습니다")
```

전체 코드는 [`예제코드/image_match.py`](../예제코드/image_match.py)에 있으며 명령어로도 쓸 수 있습니다.

```bash
cd 예제코드
python3 image_match.py crop 400 1100 300 120 button.png   # 템플릿 만들기
python3 image_match.py find button.png                    # 찾기 (위치, 점수)
python3 image_match.py tap button.png                     # 찾아서 누르기
```

```
button.png 저장 완료
(562, 1160, 0.9981)
탭: (562, 1160, 0.9981)
```

### **점수(threshold) 정하기**

| 점수 | 해석 | 조치 |
| --- | --- | --- |
| 0.95 이상 | 거의 똑같음 | 안심하고 누름 |
| 0.85 ~ 0.95 | 비슷함 (밝기·그림자 차이) | 보통 이 범위를 기준선으로 |
| 0.6 ~ 0.85 | 애매함 | 엉뚱한 곳일 수 있음, 템플릿 다시 만들기 |
| 0.6 미만 | 없음 | 화면에 버튼이 없음 |

처음에는 `find` 명령으로 버튼이 **있을 때와 없을 때** 점수를 각각 확인하고, 그 사이 값을 기준선으로 정하세요.

## 6️⃣ **이미지 매칭의 약점과 대처**

| 약점 | 원인 | 대처 |
| --- | --- | --- |
| 다른 폰에서 실패 | 해상도가 다르면 버튼 크기가 다름 | 그 폰에서 템플릿 다시 만들기, 또는 크기를 바꿔 가며 여러 번 매칭 |
| 다크 모드에서 실패 | 색이 반전됨 | 모드별 템플릿 준비 |
| 엉뚱한 곳을 누름 | 비슷한 모양이 여럿 | 템플릿을 더 특징 있게, 검색 영역 제한 |
| 느림 | 큰 화면 전체를 검색 | 화면을 줄이거나 일부 영역만 검색 |

### **예제 2: 검색 영역 제한하기**

버튼이 항상 화면 아래쪽 절반에 있다면 그 부분만 검색하면 빠르고 정확합니다.

```python
screen = grab_screen()
H = screen.shape[0]
region = screen[H // 2:, :]               # 아래쪽 절반만
res = cv2.matchTemplate(region, tpl, cv2.TM_CCOEFF_NORMED)
_, score, _, (x, y) = cv2.minMaxLoc(res)
y += H // 2                               # 잘라낸 만큼 y를 되돌림
```

### **예제 3: 흑백으로 빠르게**

색이 중요하지 않다면 흑백으로 바꾸면 계산량이 1/3로 줄어듭니다.

```python
gray_screen = cv2.cvtColor(screen, cv2.COLOR_BGR2GRAY)
gray_tpl = cv2.cvtColor(tpl, cv2.COLOR_BGR2GRAY)
res = cv2.matchTemplate(gray_screen, gray_tpl, cv2.TM_CCOEFF_NORMED)
```

## 7️⃣ **움직이는 화면 다루기: 자동 회전 배너**

쇼핑·여행 앱의 홈 화면에는 여러 장의 이벤트 배너가 몇 초마다 자동으로 넘어가는 경우가 많습니다. 4장의 예제 3처럼 쪽번호를 읽어서 누르려고 하면 이런 문제가 생깁니다.

```
문제 상황

  화면 읽기 시작 (uiautomator dump ≈ 1~2초)
        │                   ← 그 사이 배너가 6번 → 7번으로 넘어감
        ▼
  "지금 6번 배너" 라고 판단  → 탭 → 실제로는 7번이 눌림 ❌
```

### **대처법 비교**

| 방법 | 원리 | 장점 | 단점 |
| --- | --- | --- | --- |
| ① 주소로 열기 (7장) | 배너가 여는 페이지를 직접 엶 | 가장 확실 | 주소를 찾아야 함 |
| ② 이미지 매칭 후 즉시 탭 | 캡처(0.3초)가 dump보다 빠름 | 대부분 성공 | 템플릿 필요 |
| ③ 누른 채 넘기기 | 손가락이 닿아 있는 동안 자동 회전 멈춤 | 번호 고정 | 앱마다 다름 |

### **예제 4: 원하는 배너가 올 때까지 기다렸다가 누르기**

```python
from image_match import grab_screen, find_image
from adb_helper import tap
import time

TARGET = "sale_banner.png"   # 원하는 배너 그림의 일부를 잘라 둔 템플릿

for _ in range(40):                       # 최대 약 20초 동안
    screen = grab_screen()
    hit = find_image(TARGET, threshold=0.9, screen=screen)
    if hit:
        tap(hit[0], hit[1])               # 찾은 즉시 탭
        print("✅ 원하는 배너를 눌렀습니다", hit)
        break
    time.sleep(0.5)
else:
    print("❌ 배너가 나타나지 않았습니다")
```

캡처와 매칭은 합쳐서 0.3~0.5초 정도라 배너가 넘어가기 전에 누를 수 있습니다. 그래도 배너가 여는 페이지의 주소를 찾을 수 있다면(7장) 그쪽이 가장 확실합니다.

## 📝 **핵심 개념 정리**

이미지 매칭은 글자도 주소도 없고 위치도 일정하지 않은 버튼을 찾을 때 씁니다. 버튼의 특징 있는 부분을 잘라 템플릿으로 만들고, `cv2.matchTemplate`으로 화면 전체에서 점수를 계산해 `cv2.minMaxLoc`으로 최고점 위치를 찾습니다.

점수는 1에 가까울수록 똑같으며 보통 0.85 이상을 기준으로 합니다. 결과 위치는 템플릿의 왼쪽 위이므로 너비·높이의 절반을 더해 가운데를 누릅니다. 이미지 배열은 `[y, x]` 순서로 자릅니다.

해상도와 다크 모드가 바뀌면 템플릿을 다시 만들어야 합니다. 검색 영역을 줄이거나 흑백으로 바꾸면 빨라집니다. 자동으로 넘어가는 배너는 주소로 여는 것이 가장 좋고, 안 되면 빠른 이미지 매칭으로 찾는 즉시 누릅니다.

### **과제 2: 버튼 상태 판별기**

어떤 버튼이 "켜짐/꺼짐" 두 가지 모양을 가질 때(예: 좋아요 ♡/♥), 두 템플릿의 점수를 비교하여 현재 상태를 출력하는 함수를 만드세요.

```python
# 힌트
def button_state():
    screen = grab_screen()
    on = find_image("like_on.png", threshold=0, screen=screen)
    off = find_image("like_off.png", threshold=0, screen=screen)
    return "켜짐" if on and (not off or on[2] > off[2]) else "꺼짐"
```
