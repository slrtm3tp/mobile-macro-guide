## 📚 **학습 목표 (Learning Objectives)**

이번 장을 마치면 여러분은 매크로가 실패했을 때 증상을 보고 원인을 좁혀 가는 방법을 익힐 수 있습니다. 연결, 입력, 화면 읽기, 예약 실행에서 자주 생기는 문제의 해결법을 정리하고, 계정 정지나 보안 사고 없이 매크로를 쓰기 위한 약관·보안 수칙을 이해하게 됩니다.

## 1️⃣ **문제를 좁혀 가는 순서**

매크로가 안 될 때는 아래에서 위로, 기초부터 확인합니다.

```
          ┌──────────────────────────┐
     5층  │ 매크로 논리 (STEPS 순서)   │  ← 단계가 맞나? 대기가 충분한가?
          ├──────────────────────────┤
     4층  │ 화면 상태 (팝업·로그인)     │  ← 실패 순간 캡처를 보면 바로 보임
          ├──────────────────────────┤
     3층  │ 요소 찾기 (글자·좌표)      │  ← dump에 그 글자가 있나? 좌표 맞나?
          ├──────────────────────────┤
     2층  │ 명령 실행 (adb shell)     │  ← 터미널에서 직접 쳐도 되나?
          ├──────────────────────────┤
     1층  │ 연결 (adb devices)        │  ← device 상태인가?
          └──────────────────────────┘
               ▲ 아래층부터 확인
```

### **예제 1: 진단 스크립트**

1~3층을 한 번에 점검합니다.

```python
from adb_helper import *

print("1층 연결:", devices())
check_device()

print("2층 명령:", shell("echo ok"))
print("   해상도:", screen_size())
print("   현재 앱:", current_app())

root = dump_ui()
words = [n.get("text") for n in root.iter("node") if n.get("text")]
print(f"3층 화면 글자 {len(words)}개:", words[:10])
screenshot("diagnose.png")
print("   캡처: diagnose.png")
```

```

2층 명령: ok
   해상도: (1440, 3120)
   현재 앱: ('ctrip.english', 'com.ctrip.ibu.hybrid.v2.container.TripH5Container')
3층 화면 글자 12개: ['할인쿠폰 & 깜짝딜', '간사이 여행', ...]
   캡처: diagnose.png
```

## 2️⃣ **연결 문제**

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `unauthorized` | 폰에서 허용 안 함 | 폰 잠금 해제 → 허용. 안 되면 `adb kill-server` → `adb devices` |
| 목록이 비어 있음 | 충전 전용 케이블, USB 디버깅 꺼짐 | 데이터 케이블로 교체, 알림창에서 USB 모드를 "파일 전송"으로 |
| `offline` | 연결 꼬임 | 케이블 다시 꽂기, `adb kill-server` |
| `more than one device/emulator` | 기기 2대 이상 | `adb -s 시리얼 ...` |
| `adb: command not found` | 설치 안 됨 또는 PATH 없음 | `brew install android-platform-tools`, 예약 실행이면 전체 경로 |
| 무선 연결이 자꾸 끊김 | 폰 절전, Wi-Fi 변경 | 개발자 옵션에서 무선 디버깅 다시 켜고 `adb connect` |

### **예제 2: 실제로 겪은 unauthorized**

```bash
adb devices
# R5CT1234ABC	unauthorized      ← 허용 창을 놓친 상태

adb kill-server
adb start-server
adb devices
# R5CT1234ABC	device            ← 서버 재시작 후 허용 반영
```

## 3️⃣ **명령·입력 문제**

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `can't open file '.../macro.py'` | 터미널이 다른 폴더에 있음 | `cd 예제코드` 후 실행, 또는 전체 경로로 실행 |
| `ModuleNotFoundError: adb_helper` | 다른 폴더에서 실행 | `예제코드` 폴더 안에서 실행 |
| 주소가 중간에서 잘림 | 폰 셸이 `&`를 명령 구분자로 읽음 | `"'주소'"`처럼 두 번 감싸기 (7장) |
| 띄어쓰기가 사라짐 | `input text`는 공백 불가 | `%s` 사용 |
| 한글이 안 들어감 | `input text`는 ASCII만 | ADBKeyboard(9장) 또는 uiautomator2(10장) |
| 탭이 가끔 무시됨 | 앱이 아직 그리는 중 | `wait_for`로 요소가 나타난 뒤 탭 |
| 스와이프가 너무 멀리 감 | 시간이 짧아 관성 발생 | 시간을 400~800ms로 늘리기 |

## 4️⃣ **화면 읽기 문제**

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 캡처가 검은 화면 | 앱이 캡처 차단 (은행·증권·일부 게임) | 그 앱은 화면 읽기 불가. 매크로 대상에서 제외 |
| `uiautomator dump` 실패 (`ERROR: could not get idle state`) | 애니메이션·영상이 계속 움직임 | 잠시 후 재시도, 영상 정지, uiautomator2 사용 |
| 글자 목록이 거의 비어 있음 | 게임·웹 화면 | 좌표, 이미지 매칭(8장), 주소로 열기(7장) |
| 글자를 찾았는데 눌러도 반응 없음 | 글자가 누를 수 없는 요소, 위에 다른 창이 덮음 | 부모(`clickable="true"`) 요소 사용, PIP·팝업 닫기 |
| 좌표가 어긋남 | 화면 회전, 다른 해상도 | `wm size`와 방향 확인 후 다시 측정 |
| 배너 번호가 계속 바뀜 | 자동 회전 | 주소로 바로 열기 (7장) |
| 이미지 매칭 점수가 낮음 | 해상도·다크 모드 차이 | 그 폰·그 모드에서 템플릿 다시 만들기 |

### **예제 3: 덮고 있는 창 찾기 (실제 사례)**

유튜브를 보다가 트립닷컴으로 넘어가면 유튜브 미니 플레이어(PIP)가 화면 위쪽을 덮습니다. 그 아래 버튼을 탭하면 PIP가 터치를 가져갑니다.

```bash
adb shell dumpsys window | grep -E "mCurrentFocus|pip" | head
```

캡처로 확인하는 것이 가장 빠릅니다. 매크로 시작 전에 홈 키를 눌러 PIP를 정리하거나, 유튜브를 종료합니다.

```python
stop("com.google.android.youtube")   # PIP 닫기
```

## 5️⃣ **예약 실행 문제**

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 터미널에선 되는데 cron에선 안 됨 | PATH, 작업 폴더 차이 | 전체 경로, `cd 폴더 &&` 먼저 |
| cron 로그가 아예 없음 | 권한 부족 (macOS) | 전체 디스크 접근 권한에 cron 추가 |
| 정해진 시각에 실행 안 됨 | Mac 잠자기 | `caffeinate`, launchd 사용 |
| 실행됐지만 폰이 반응 없음 | 폰 화면 꺼짐·잠금 | 시작 시 `KEYCODE_WAKEUP`, 충전 중 화면 켜짐 유지 |

## 6️⃣ **안전 수칙: 약관**

매크로는 기술적으로 가능하더라도 **서비스 약관이 금지하는 경우**가 많습니다. 위반하면 계정 정지, 혜택 회수, 법적 문제가 생길 수 있습니다.

| 용도 | 위험도 | 설명 |
| --- | --- | --- |
| 내 폰 설정 바꾸기, 앱 테스트 | 🟢 낮음 | 내 기기, 내 앱 |
| 페이지를 정해진 시각에 열어 두기 | 🟢 낮음 | 사람이 할 행동을 대신 준비 |
| 쿠폰 버튼 한 번 누르기 | 🟡 보통 | 서비스마다 다름, 약관 확인 |
| 게임 자동 사냥, 자동 반복 | 🔴 높음 | 대부분의 게임 약관이 명시적으로 금지 |
| 티켓·한정판 선착순 매크로 | 🔴 높음 | 금지 + 다른 사용자에게 피해 |
| 여러 계정으로 반복 참여 | 🔴 높음 | 부정 참여로 혜택 회수·정지 |

> 💡 판단 기준: "사람이 직접 하는 것과 같은 속도·횟수로, 내 계정 하나로, 내가 할 행동을 편하게 하는 것"이면 비교적 안전합니다. 사람보다 빠르게 남보다 먼저 가져가는 용도라면 하지 않는 것이 좋습니다.

## 7️⃣ **안전 수칙: 보안**

| 수칙 | 이유 |
| --- | --- |
| USB 디버깅은 쓸 때만 켜기 | 켜져 있으면 연결된 PC가 폰을 거의 전부 조작할 수 있음 |
| 모르는 PC의 디버깅 허용 창은 거절 | 공용 충전기·PC를 통한 조작 방지 |
| 무선 디버깅은 집 Wi-Fi에서만, 쓰고 나면 끄기 | 같은 네트워크의 다른 기기가 접근 시도 가능 |
| 비밀번호·카드번호를 스크립트에 쓰지 않기 | 파일 유출, GitHub 업로드 시 노출 |
| 로그인·결제는 사람이 직접 | 오작동 시 금전 피해 |
| APK·스크립트는 공식 출처에서만 | 악성 매크로 앱은 접근성 권한으로 화면을 훔쳐볼 수 있음 |
| 접근성 권한은 신뢰하는 앱에만 | 화면 내용 읽기·조작이 가능한 강력한 권한 |
| GitHub에 올릴 때 시리얼·개인 주소 지우기 | 기기 식별 정보 노출 방지 |

### **예제 4: 디버깅 권한 정리하기**

매크로를 다 쓴 뒤에는 이렇게 정리합니다.

```
설정 → 개발자 옵션
   ├── USB 디버깅 권한 승인 취소   (허용했던 PC 목록 초기화)
   ├── 무선 디버깅                 (끄기)
   └── USB 디버깅                  (필요 없으면 끄기)
```

## 📝 **핵심 개념 정리**

매크로 문제는 연결 → 명령 → 요소 찾기 → 화면 상태 → 매크로 논리 순서로 아래층부터 확인합니다. 진단 스크립트와 실패 순간 캡처가 원인을 가장 빨리 알려 줍니다.

연결 문제는 대부분 허용·케이블·`adb kill-server`로, 입력 문제는 따옴표·`%s`·한글 입력 도구로, 화면 읽기 문제는 대기·덮인 창 정리·다른 찾기 방법으로 해결합니다. 예약 실행은 PATH와 작업 폴더, 잠자기를 확인합니다.

매크로는 약관이 허용하는 범위에서 사람과 같은 속도로 내 계정 하나로만 사용합니다. USB·무선 디버깅은 쓸 때만 켜고, 비밀번호는 스크립트에 적지 않으며, 접근성 권한과 APK는 신뢰할 수 있는 곳에만 줍니다.

## 🔑 **퀴즈 정답 및 해설**

**1번 정답: 2**
연결이 안 되어 있으면 위층의 모든 것이 실패합니다. 항상 1층(연결)부터 확인합니다.

**2번 정답: 2**
은행·증권 앱 등은 화면 캡처를 막는 보안 설정(FLAG_SECURE)을 사용합니다. 이런 앱은 화면 읽기 기반 매크로가 불가능합니다.

**3번 정답: 2**
`adb_helper`는 pip 패키지가 아니라 이 강의의 파일입니다. Python은 현재 폴더에서 모듈을 찾으므로 같은 폴더에서 실행해야 합니다.

**4번 정답: 3**
페이지를 미리 열어 두는 것은 사람이 할 행동을 준비해 주는 수준입니다. 나머지는 대부분의 서비스 약관이 금지합니다.

**5번 정답: 3**
USB 디버깅이 켜져 있고 모든 PC를 허용하면, 연결된 PC가 폰의 화면을 읽고 조작할 수 있어 매우 위험합니다.
