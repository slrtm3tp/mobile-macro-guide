## 1️⃣ **모바일 매크로란?**

모바일 매크로는 **사람 대신 스마트폰 화면을 누르고, 밀고, 입력하는 프로그램**입니다. 매일 아침 같은 앱을 열어 출석 버튼을 누르거나, 매주 수요일 쿠폰 페이지를 여는 것처럼 반복되는 작업을 자동으로 처리할 수 있습니다.

```
사람이 할 때                          매크로가 할 때

  👆 앱 아이콘 터치                     💻 adb shell monkey -p 앱 ...
  ⏳ 로딩 기다리기                      ⏳ time.sleep(3)
  👆 이벤트 탭 터치                     💻 adb shell input tap 540 300
  👆 배너 터치                          💻 adb shell input tap 400 1200
  👀 쿠폰 받았는지 확인                 💻 화면을 읽어서 "받기 완료" 확인
```

매크로는 결국 **사람이 하는 동작을 명령어로 바꾸어 순서대로 실행하는 것**입니다. 이 강의에서는 안드로이드 폰을 PC에서 조종하는 ADB(Android Debug Bridge)를 중심으로 배웁니다.

### **모바일 매크로를 만드는 방법들**

| 방식 | 어디서 실행 | 지원 폰 | 난이도 | 장점 | 단점 |
| --- | --- | --- | --- | --- | --- |
| **ADB + Python** | PC | 안드로이드 | 쉬움 | 무엇이든 가능, 원리 이해에 최적 | PC와 연결 필요 |
| uiautomator2 | PC | 안드로이드 | 보통 | 글자·ID로 찾기가 매우 편리 | 폰에 도우미 앱 설치 |
| Appium | PC | 안드로이드·iOS | 어려움 | 업계 표준 테스트 도구 | 설정이 복잡 |
| MacroDroid · Tasker | 폰 안 | 안드로이드 | 쉬움 | PC 없이 동작 | 복잡한 화면 판단이 약함 |
| 단축어(Shortcuts) | 폰 안 | iOS | 쉬움 | 기본 앱 | 화면 좌표 탭 불가 |

이 강의는 **ADB + Python**으로 원리를 익힌 뒤, 10장에서 uiautomator2 같은 편리한 도구로 넘어가는 순서로 진행합니다.

## 2️⃣ **ADB의 동작 원리**

ADB는 PC와 안드로이드 기기 사이에서 명령을 주고받는 통로입니다. 세 부분으로 이루어져 있습니다.

```
ADB 구조

  ┌──────────── PC ────────────┐          ┌──────── 안드로이드 폰 ────────┐
  │                            │   USB    │                              │
  │  adb 클라이언트 (터미널)     │  또는    │  adbd (폰 안의 ADB 데몬)      │
  │        │                   │  Wi-Fi   │        │                     │
  │        ▼                   │ ───────► │        ▼                     │
  │  adb 서버 (포트 5037)       │          │  input / am / pm / screencap │
  └────────────────────────────┘          └──────────────────────────────┘
```

- **adb 클라이언트**: 우리가 터미널에 입력하는 `adb` 명령입니다.
- **adb 서버**: PC에서 백그라운드로 돌며 연결된 기기들을 관리합니다. `adb kill-server`로 재시작할 수 있습니다.
- **adbd**: 폰 안에서 명령을 받아 실행하는 프로그램입니다. USB 디버깅을 켜야 동작합니다.

`adb shell input tap 540 1200`을 입력하면 PC의 명령이 폰으로 전달되고, 폰 안의 `input` 프로그램이 (540, 1200) 위치를 터치한 것처럼 동작합니다.

## 3️⃣ **ADB 설치하기**

### **Mac**

Homebrew가 설치되어 있다면 한 줄로 끝납니다.

```bash
brew install android-platform-tools
```

설치가 끝나면 버전을 확인합니다.

```bash
adb version
```

```
Android Debug Bridge version 1.0.41
Version 37.0.1
...
```

### **Windows**

1. [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools) 페이지에서 Windows용 zip을 받습니다.
2. `C:\platform-tools` 처럼 알기 쉬운 곳에 압축을 풉니다.
3. 시스템 환경 변수 `Path`에 `C:\platform-tools`를 추가합니다.
4. 새 명령 프롬프트를 열고 `adb version`을 입력합니다.

### **Python 확인**

5장부터 Python을 사용합니다. 버전을 확인해 둡니다.

```bash
python3 --version
```

```
Python 3.14.0
```

3.8 이상이면 이 강의의 예제를 모두 실행할 수 있습니다.

## 4️⃣ **폰 설정: 개발자 옵션과 USB 디버깅**

ADB가 폰을 조종하려면 폰에서 허락해 주어야 합니다.

### **1단계: 개발자 옵션 켜기**

```
설정 → 휴대전화 정보 → 소프트웨어 정보 → 빌드번호  (7번 연속 터치)

  "개발자 모드를 켰습니다" 메시지가 나오면 성공
```

갤럭시 기준 경로입니다. 다른 제조사는 `설정 → 휴대전화 정보 → 빌드 번호`처럼 조금 다를 수 있습니다.

### **2단계: USB 디버깅 켜기**

```
설정 → 개발자 옵션 → USB 디버깅  (켜기)
```

### **3단계: 연결하고 허용하기**

1. **데이터 전송이 되는 케이블**로 폰과 PC를 연결합니다. 충전 전용 케이블은 인식되지 않습니다.
2. 폰 잠금을 풀면 "USB 디버깅을 허용하시겠습니까?" 창이 뜹니다.
3. **"이 컴퓨터에서 항상 허용"**에 체크하고 **허용**을 누릅니다.

## 5️⃣ **연결 확인: adb devices**

```bash
adb devices
```

```
List of devices attached
SERIAL	device
```

첫 번째 칸은 기기의 **시리얼 번호**, 두 번째 칸은 **상태**입니다.

| 상태 | 의미 | 해결 방법 |
| --- | --- | --- |
| `device` | 정상 연결 | 바로 사용 가능 |
| `unauthorized` | 폰에서 아직 허용하지 않음 | 폰 잠금 해제 후 허용 → 안 되면 `adb kill-server` 후 다시 `adb devices` |
| `offline` | 연결이 불안정 | 케이블 다시 연결, `adb kill-server` |
| 목록이 비어 있음 | 인식 실패 | 데이터 케이블 확인, USB 디버깅 다시 켜기 |

### **예제 1: unauthorized 해결하기**

실제로 가장 많이 만나는 문제입니다. 허용 창을 놓쳤거나 화면이 잠겨 있을 때 생깁니다.

```bash
# 1. 현재 상태 확인
adb devices
# SERIAL	unauthorized

# 2. 폰 잠금을 풀고 허용 창이 떠 있는지 확인 → 허용

# 3. 허용 창이 안 보이면 adb 서버를 재시작해서 창을 다시 띄움
adb kill-server
adb devices
# * daemon not running; starting now at tcp:5037
# * daemon started successfully
# SERIAL	device
```

그래도 허용 창이 뜨지 않으면 `개발자 옵션 → USB 디버깅 권한 승인 취소`를 누르고 케이블을 다시 꽂습니다.

### **예제 2: 기기 정보 알아보기**

연결이 되었다면 폰의 기본 정보를 확인해 봅니다. 매크로를 만들 때 해상도는 꼭 알아야 합니다.

```bash
# 모델명
adb shell getprop ro.product.model
# SM-S948N

# 안드로이드 버전
adb shell getprop ro.build.version.release
# 16

# 화면 해상도 (가로x세로 픽셀)
adb shell wm size
# Physical size: 1440x3120

# 화면 밀도
adb shell wm density
# Physical density: 600
```

## 6️⃣ **무선으로 연결하기**

케이블 없이 Wi-Fi로도 연결할 수 있습니다. **폰과 PC가 같은 Wi-Fi**에 있어야 합니다.

### **방법 A: 무선 디버깅 (안드로이드 11 이상)**

```
설정 → 개발자 옵션 → 무선 디버깅 (켜기)
       → "페어링 코드로 기기 페어링" 터치

  화면에 표시되는 정보:
    Wi-Fi 페어링 코드: 482913
    IP 주소 및 포트:   192.168.0.12:37123
```

```bash
# 1. 페어링 (처음 한 번만)
adb pair 192.168.0.12:37123
# Enter pairing code: 482913
# Successfully paired to 192.168.0.12:37123

# 2. 연결 (무선 디버깅 화면 위쪽의 "IP 주소 및 포트" 사용 - 페어링 포트와 다름!)
adb connect 192.168.0.12:41234
# connected to 192.168.0.12:41234

adb devices
# 192.168.0.12:41234	device
```

### **방법 B: tcpip 모드 (구형 폰)**

USB로 한 번 연결한 상태에서 무선으로 전환합니다.

```bash
adb tcpip 5555                  # 폰을 5555 포트로 대기시킴
adb shell ip route | awk '{print $9}'   # 폰의 IP 확인 (예: 192.168.0.12)
# 케이블 분리
adb connect 192.168.0.12:5555
```

## 📝 **핵심 개념 정리**

모바일 매크로는 사람이 폰에서 하는 터치, 스와이프, 입력을 명령어로 바꾸어 자동으로 실행하는 프로그램입니다. 안드로이드에서는 PC의 ADB로 폰을 조종하는 방식이 가장 강력하고 배우기 쉽습니다.

ADB는 PC의 클라이언트와 서버, 폰 안의 adbd로 이루어집니다. 폰에서 개발자 옵션과 USB 디버깅을 켜고, 연결 시 뜨는 허용 창에서 허용해야 합니다.

`adb devices`의 상태가 `device`이면 정상입니다. `unauthorized`는 폰에서 허용하지 않은 상태이며, `adb kill-server`로 서버를 재시작하면 대부분 해결됩니다. 안드로이드 11 이상에서는 `adb pair`와 `adb connect`로 무선 연결도 가능합니다.

## 🔑 **퀴즈 정답 및 해설**

**1번 정답: 2**
`unauthorized`는 폰이 이 PC를 아직 허락하지 않았다는 뜻입니다. 폰 잠금을 풀면 허용 창이 보입니다. 창이 없으면 `adb kill-server` 후 `adb devices`로 다시 띄울 수 있습니다.

**2번 정답: 3**
빌드번호를 7번 연속으로 터치하면 "개발자 모드를 켰습니다"라는 메시지와 함께 개발자 옵션이 나타납니다.

**3번 정답: 2**
`adb kill-server`는 PC의 adb 서버를 종료합니다. 다음 adb 명령을 실행하면 서버가 자동으로 다시 시작됩니다. `adb reboot`는 폰을 재부팅하므로 주의해야 합니다.

**4번 정답: 2**
가로 1080의 절반은 540, 세로 2400의 절반은 1200입니다. 좌표는 (x, y) = (가로, 세로) 순서입니다.

**5번 정답: 3**
페어링 코드 창에 나오는 포트는 페어링 전용입니다. 실제 연결은 무선 디버깅 메인 화면의 "IP 주소 및 포트"를 사용하며 두 포트는 다릅니다.
